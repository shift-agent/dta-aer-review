How the offline inventory plan works

Built and proven, not hypothetical — this is the exact mechanism keeping staging.decortoadore.com up right now, while the Current RMS credential is dead (item 4 today). No visitor-facing downtime, no partial or broken catalog, ever.

The process, step by step

Every catalog sync is all-or-nothing. It either finishes completely and becomes the live catalog, or it changes nothing at all — there is no in-between state a visitor can ever land on.

1

A live Current RMS sync runs

On its own schedule (hourly) or triggered manually — it asks Current RMS for the current products, fabrics, catalog and groups.

2

The result is staged, never written in place

All datasets, plus a manifest, are written as JSON files into a fresh, uniquely-IDed folder under catalog/generations/<uuid>/. Nothing that’s currently live is touched while this happens.

3

Everything must write completely and successfully, or nothing changes

One gate, two outcomes:

✓

Writes completely & successfully

The new generation is promoted — atomically marked the one the storefront reads. The last few prior generations are kept, older ones pruned.

✗

Fails, or Current RMS is unreachable

The attempt is simply never promoted. The active generation pointer never moves — nothing changes for visitors.

Today’s real state · HTTP 401
4

The storefront only ever reads the active generation

Every product and category page is served from whichever generation is currently marked active — the storefront has no idea whether the last sync attempt succeeded or failed.

5

Result: zero visitor-facing downtime

When a sync fails — like today’s dead credential — the storefront keeps serving the last generation that did succeed. No error, no blank page, no partial catalog. A visitor browsing the site right now cannot tell the difference.

Approved photos ride the same mechanism

As of Simplitory v0.2.3, an approved product photo isn’t queued for the next sync — it’s baked directly into the current active generation’s own catalog and product files the moment it’s approved. Photo updates are live-safe on their own timeline, independent of whether a live Current RMS sync is currently working at all.

Why this matters for DTA

The short version: the site doesn’t wait on IT.

The site stays live while the credential gets sorted out

Item 4 on today’s agenda — the dead Current RMS key — is a real, separate problem, but it isn’t blocking anything visitor-facing. Staging is up right now, serving the last successful generation, while that credential issue is worked in the background.

No single point of failure waiting on someone else’s system

Current RMS being unreachable, slow, or mid-maintenance never breaks the storefront. The catalog only ever moves forward from a known-good state.

This is the honest “crude but real” Phase 2

Today the sync and the manual photo drop-zone are operator-driven — a person or a clock triggers each attempt. Crude, but real: every piece above is built and running, not a plan.

A clear, non-disruptive upgrade to Phase 3

Phase 3 swaps the trigger for a fully automated Drive-watching importer — same generations, same atomic promotion, same safety net. It only makes the front end of the pipeline more automatic; nothing about how the storefront stays safe changes.
